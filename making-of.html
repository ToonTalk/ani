The making of

Ani's Cinderella, brought back

In 1978 Ken Kahn's program Ani turned a short description of the Cinderella story into an animated film. In October 2026, almost fifty years later, Ken and Claude brought Ani back. Not a copy of it: Ken's own 1978 Lisp, recovered from the MIT AI Lab's backup tapes, running unchanged in a web browser. Then they built some of what Ken's thesis said Ani should do next. This page tells how, in order, with the numbers.

Ani: Ken Kahn, MIT Artificial Intelligence Laboratory, 1978–79 (his thesis, rewritten as AI-TR-540). The revival: Ken, directing it and deciding; Claude (Anthropic's Claude Opus 5.5, working as Claude Code with many subagents), doing the engineering. 8 to 16 October 2026.

1978

Ani in 1978

Ani was the program at the heart of Ken's MIT doctoral thesis, Creation of Computer Animation from Story Descriptions (1979), which he then substantially rewrote as the technical report AI-TR-540. It was not given a script. It was given a film description, written in Lisp: who the characters are (Cinderella is shy, good and graceful; the stepmother is evil and mean), how they feel about one another, and what each scene has to get across (in one, the stepmother keeps Cinderella and the Prince apart).

From that, Ani decided for itself how each character should move, fast or slow, smoothly or jerkily, in curves or straight lines, and what each should do in each scene. It worked in two passes. Pass 1 makes 102 choices about how the characters move, each by gathering suggestions from what Ani knows about personalities, relationships and films, and settling their conflicts. Pass 2 plans each scene: how to convey what the scene must, in which parts, with whom where, and for how long. Director, the actor language Ken had written, then animated the plan.

Read the thesis. Ken's doctoral thesis is on MIT's DSpace, and so is AI-TR-540, the version he rewrote, substantially, as an AI Lab technical report. Where this page gives page numbers, quotations, appendices or chapters, it cites AI-TR-540, the rewritten version; the flipbook is in its page corners.

“It”, not “she”. This page calls Ani “it”. An early draft of Ken's thesis called Ani “she”; one professor insisted that he change it, and he did. The revival's film page called Ani “she” too, until 16 October 2026, when Ken chose “it” again.

The tapes

What the tapes held, and what they didn't

Ken's files survived on the MIT AI Lab's backup tapes. When the tapes were read, decades later, each file was saved in a format that packs each 36-bit word of the lab's PDP-10 into five bytes. Undoing it gave back the text exactly, and a few small tools decoded the binary files too: compiled Lisp, directory listings, archives, pictures.

The best tape has a directory listing dated 8 January 1979, four days before Ken submitted his dissertation. It holds all 31 of Ani's source files, about 10,000 lines, which matches the thesis's own estimate of Ani's size. It holds the Cinderella description, CINDY 46. And it holds CP 29, the file pass 1 wrote for pass 2 in September 1978: 102 choices, 54 relative and 48 absolute, the very counts the thesis gives in Appendix III. That made an exact test possible. Given CINDY, a revived Ani should make the same 102 choices.

Part of the foundation was missing. Ani is written in Director, and the lowest layer of Director, Ken's KEN1; directory, was lost: about twenty files and some 490 definitions, including the macros, the utilities, the pattern matcher and the compiler for actors. A tags table named every function in them. Their code was gone.

What survived, file by file the tapes' contents
  • Ani's 31 source files (tape 7005017, January 1979), 28 of them also compiled.
  • The Cinderella description, CINDY 46, the thesis's Appendix I.
  • Pass 1's answers, CP 29 (102 choice points), and RUN24 2, a later run that records the same choices with the suggestions behind each.
  • Ani's driver files: how pass 1, pass 2 and filming were run, and which files they passed between them.
  • Director: the files in Ken's KEN; directory, and KEN1;DRECT, the Lisp primitives Director is built on, hidden in an editor's save file. Also Director compiled into plain Lisp, which shows what the lost macros produced, and earlier and later versions on other tapes.
  • Lost: the rest of KEN1;; the five scene programs Ani wrote for Director, their summaries and the positions saved between scenes; the color turtle.

Personal files on the tapes were left out of the project.

How the tapes encode a file 36-bit words in bytes

Every file uses the "evacuate" format (described by Alan Bawden in 1992) in which ITS files were moved to Unix. Text is five 7-bit characters to a word; a word whose last bit is set is written as a marker byte and four more bytes; line ends are swapped. src/its/text.js undoes it. The few "garbled" spots in the files turned out to be ordinary words with that last bit set, and decode cleanly.

8 October, morning

Run the real thing, not an imitation

The revival began with this message from Ken to Claude:

Earlier attempts to revive Ani with AI tools had produced imitations: new programs that acted out Ani's ideas. On the first morning Ken chose the other road. Claude would write a MacLisp interpreter in JavaScript, the Lisp Ken wrote in, and Ken's 1978 files would load on top of it exactly as they are on the tape. Only what was lost would be rebuilt, and in MacLisp, not JavaScript, so that everything above the interpreter is Lisp, as it was.

Two other roads were set aside. Emulating the whole PDP-10 is possible today, but it wouldn't have helped: Ani's compiled code needs the same lost runtime. A modern rewrite of Ani was kept for later, with the revival's traces of what Ani does as its specification.

The interpreter 2,787 lines of JavaScript

A reader for ITS's syntax (in MacLisp the slash is the escape character, so division is written //) and Director's read macros; MacLisp's dynamic binding, special forms and functions that take their arguments unevaluated or in any number; property lists, catch and throw, flonum arithmetic, and about 200 built-in functions. An ITS file system serves load, include and the files the passes write. On the first day it read all 1,493 forms of Ani and Director. It runs in Node, for fast tests, and in any browser.

8 October

Rebuilding what was lost

The best evidence for the lost KEN1; code turned out to be a file called TS D2500: a Director saved in January 1980, built to drive Ken's vector display, whose memory image holds compiled code for most of the lost runtime. Claude decompiled it file by file, from PDP-10 instructions back into Lisp. Where the 1980 code might differ from 1978's, older evidence decided: the June 1978 Director Guide (AIM-482), the call sites in Ani, Director compiled into plain Lisp, and Ani's own compiled files. Every rebuilt definition cites its evidence. The result is 12 files, 2,194 lines of MacLisp.

The same day, the TV turtle Director drew with was ported from LLOGO's public source, and Director's own demos ran unchanged.

Compiled code that reads nothing as zero a 1978 quirk the revival has to copy

Ani's compiled 1978 code checks no types. In it NIL, Lisp's empty list, reads as the number 0 (it lived at memory location 0), and a list reads as a negative number. Two of Ani's paths, in the quadrants of its stage geometry and in the elapsed time of an action, only work because of that. So the revival emulates it there, citing the compiled code.

8 October, midday

The tape caught Director in the middle of a rewrite

Getting Ani's choices to match uncovered a piece of history. Ani's compiled files call functions, such as RECALL-VARIABLE and CHANGE-VALUE, that the surviving Director doesn't have. The second Director Guide explained why: much of Director had been rewritten, and its "demons" removed. Ken had rewritten Director around 21 November 1978, after Ani was written and two months after CP 29 was made by the old Director. The Director on the tape, dated January 1979, is the new one.

So the revival has a bridge, REVIVE;BRIDGE, loaded after Director, which puts back what the old Director did for Ani. Each change is argued from the evidence: the 1978 Guide, Ani's compiled files, Ken's own partial bridge of 22 November 1978, TS D2500, or CP 29 itself. Ken didn't remember whether he ran Ani after November 1978; the evidence says Cinderella was made on the old Director.

What the bridge puts back 620 lines
  • A message's :self is the name it was sent to, as in 1978, not the actor itself.
  • "Demons" on variables are kept in the variables, as the 1978 Guide says, so that a save keeps them; demons on the database (virtual items, actions on memorizing) are rebuilt from the Guide.
  • INTERSECT keeps its second set's order, and that order decides the order in which Ani makes its choices. The 1980 one keeps the first's.
  • "Make copy" makes an independent twin that differs only in name, using COPY as TS D2500 has it; scenes save a copy of themselves before planning, and restore it when they must stretch.
  • "Forget your" takes patterns; saves list variables oldest first, as the thesis's Appendix VI shows.
  • Filming in color as ANINIT did, with the 1978 definitions Ken kept only in a comment or in an unloaded file.

8 October, evening

Five scenes, planned and filmed

Pass 2 plans each scene from where Director left the characters at the end of the one before, so the five go in order: plan a scene, film it, save the positions, plan the next. By 17:52 on the first day Ani had planned all five scenes and Director had filmed them; by 18:50 they were in color.

The plans read as the thesis describes them. The Introduction has five parts, estimated at 42.2 seconds (the thesis: 43.3 estimated, 42 real). Kept Apart's first part has the values the thesis prints in Appendix VI, and in its second the stepmother stands guard six times where four were planned, stretched by Ani as the thesis says. Appendix III says pass 2 begins with 418 actors and makes 154 more; the revival begins with 343 and makes 147.

What is still open small differences from the thesis
  • Appendix VI gives Cinderella high speed in Kept Apart's first part; the revival's is low. Both estimate it at 1.53 seconds, which points to low at the time of the estimate.
  • Appendix VI numbers her dynamics -26; the revival's are -7, or -28 when the scenes are planned in one job, as Ken's driver allows.
  • Within that part the locations come in another order, and the Introduction has a fifth, empty part where the thesis describes four.
8 October

Frame by frame against the thesis's flipbook

AI-TR-540, the rewritten thesis, prints frames of the film in the corners of its pages, so that flipping the pages animates them. Claude recovered all 574 frames from the scanned report, registered so that they line up: a complete record of a 1978 run, at 4 frames a second, made by the same program on the same description. It became the ground truth for the film.

Kept Apart matches closely from start to finish, and its parts begin on the same frames. The Introduction matches exactly for its first 61 frames; then the stepmother's fourth push starts a frame or two late and drifts by about a shape's width. Nothing in the movement code is random, and rounding every number to the PDP-10's precision changed no frame. The likeliest cause is Director's object code of January 1979, since the 1978 one is lost.

The flipbook also settled two questions. The picture was 550 by 413 dots: at the TV's full size the Introduction runs 15 frames longer. And in 1978 Director's universe emptied its list of actors while they were taking their turns, so a check made during a turn could end the film early. That is what the flipbook shows: Kept Apart ends just after its third part, with the stepmother still standing guard.

9 October

Four frames a second, and twenty-four

Ken's TV previews ran at 4 frames a second, and so does the run in the flipbook. The film itself was shot at 24: Ken's setup for filming in color sets 24 frames a second. The YouTube transfer of his 16mm print agrees: its picture changes on about 21 of every 30 video frames. Director divides each movement by the frame rate, so at 24 the characters take smaller steps. Ani makes the same choices, but the scenes leave the characters in slightly different places, so from No Longer Kept Apart on the two are different runs of the same plans.

At 24 frames a second the scenes last 38.2, 29.2, 4.7, 43.8 and 19.1 seconds. The film page shows the 1978 film at 24 by default, with a switch to 4. In color, Ken's setup drew each shape again inside itself every 10 dots (every 20 for the denser star), so that it looked filled on the color screen; the 1978 definition survived only in a comment, and the bridge supplies it.

9 October

Ken's voice

The 1978 film's soundtrack is Ken's narration, under mains hum, a whistle near 1,636 Hz that wanders with the film's speed, a band of noise near 800 Hz, and the projector's clatter at 24 a second. Notch filters, and a filter that follows the quietest level in each band, brought the speech to 9 to 15 decibels above the pauses, from 4.6.

Ken spoke a line as each shot began. So the narration was cut at its pauses and laid onto the revived 24-frames-a-second film shot by shot, each line where the same shot begins. Kept Apart and No Longer Kept Apart run 29.2 and 4.7 seconds in both films.

9 October

A film you can question

By the morning of the second day the film was a web page: one self-contained file, the film on its TV screen beside the film description in plain English. The default view is simple, and the details are a click away, as Ken asks of every glass box.

Click any character, at any frame, and the glass box says what it is doing and why: the chain of tasks behind it back to the description's own words, the ways of showing it that Ani weighed and rejected, the plan in Ani's words, where the part started and why, and how the character moves, each value traced to the method that set it or to pass 1's choice and that choice's suggestions. Ani's code has a page of its own, every name linked to its definition. That morning the site went live at toontalk.github.io/ani.

9 October

Changing the story

"Change the story" edits the characters' words and relationships, offering only words Ani knows, or the Lisp itself. "Make the film" then runs the real thing in the browser: the interpreter, Director, the bridge and Ken's files, with the changed description in place of his. Pass 1 takes about 18 seconds, the whole film two or three minutes. Each scene plays beside 1978's as soon as it is made, with what changed: the words, pass 1's choices and their reasons, and each scene's parts.

The changed stories taught things about Ani:

  • A kind stepmother who loves Cinderella changes 21 of the 102 choices; in the Introduction she goes to Cinderella and keeps her company instead of hitting, chasing and pushing her.
  • For many changes Ani plans the same actions and only the movement changes. The plot lives in the scene descriptions: a wicked fairy godmother still rescues Cinderella, because the scene says she does.
  • A defiant Cinderella stops pass 2: pass 1 can choose "not high" for the stepmother, and a later part of Ani accepts only low, medium or high. Ken's description never led there, so 1978 never met it.
9 to 13 October

New stories from language models

"Tell Ani a new story" asks a language model to put a story into Ken's notation, using only the words Ani knows: Claude, ChatGPT or Gemini with the visitor's own key, Gemini Nano built into Chrome, or, in a copy of the page made for claude.ai, Claude on the visitor's own account with no key at all. It is a modern take on the thesis's section X.E, on film descriptions that come from the program instead of a person. The reply is checked for words Ani doesn't know, tasks Ani can't show, characters or relationships never defined, and "Ask the model to fix these" sends the problems back. The description opens in the editor before Ani makes the film.

New stories found gaps that Ken's Cinderella never reached:

  • Ani asks how a friendly character feels about each of the others in turn, without checking that the story says. Ken's description relates Cinderella to everyone, so it never mattered.
  • One way of showing that two characters meet asks for a display method, move-to, that Ani never defines.
  • A villain's victim, or a friend, can be picked from outside the scene; one who never comes on stage leaves a scene that never ends. The page stops filming at 250 seconds, Ken's own 1,000 frames.

JSON or Lisp? Ken wondered whether models write JSON better than Lisp. An A/B test sent the same 15 stories both ways. With the strongest model (GPT-6.1 Sol) the two told their stories equally well, and Ani filmed 55 of 64 scenes from the Lisp drafts and 56 of 63 from the JSON. With a cheaper one (GPT-6 Luna) 6 of 15 Lisp drafts had parentheses out of place and one story was still broken after two rounds of fixes; none of the JSON drafts had a problem. JSON became the default, translated by the page into Ken's notation, which is still what the reader sees and edits.

The trials 105 drafts, 15 stories
  • 15 stories (the page's three examples and twelve fairy tales and fables), drafted by two OpenAI models through the page's own prompt by tools/try-stories.mjs: 15 drafts on 11 October, then 90 in the A/B test of 13 October (GPT-6.1 Sol in two rounds and GPT-6 Luna, each in Lisp and in JSON), 105 in all, with 6 rounds of fixes.
  • Ani made every GPT-6.1 Sol draft, scene by scene. Of the fifteen of 11 October, five stopped on a way of showing that Ken named but never finished, and three hung or overflowed the stack with two characters standing at one place; with the repairs of the next section, every scene of all fifteen is filmed.
  • Ken tried Gemini Nano in Chrome himself, and stories from his tests became test stories.
  • Claude's reviewers wrote stories of their own to break each stage: 25 to try the new knowledge (stage 4), 15 to try characters who change (stage 6), and more.
9 to 15 October

Chapter X: what Ani might do next, as switches

The thesis ends with a chapter, Chapter X, on what Ani might do next: choose how the characters look, change their looks during a film, let characters change, know more, and pay attention to more details. On the second afternoon Claude ran a workflow of thirteen agents: four read the thesis, Ani's code, the revival and the Agent Kit; four designed the extensions; four reviewers attacked the designs; one combined what survived into a plan. Ken settled its open questions that evening. The rules:

  1. Each extension is Lisp, written in Ken's idioms, in a file of its own (REVIVE;MEND, REVIVE;APPEAR, ...), so the glass box explains it as it explains Ken's code.
  2. "Ani as in 1978" stays byte for byte. tools/check-1978.mjs checks CP 29, every scene program, summary, glass box, frame and event against the 1978 run, with no extensions and with each that shouldn't change Cinderella.
  3. The site opens in 1978 mode. A switch turns on the revival's extensions (now MEND, KNOW, APPEAR, CHANGE and SEEN); SLIPS and DETAIL are ticked one by one.
  4. The revival may add knowledge the thesis doesn't state, labeled as the revival's, with its reason; none of it may give back Ken's 1978 looks by itself.

MEND: repairs for new stories

repairsstage 1, 9 to 15 October

Twenty repairs (M1 to M20) for the failures new stories hit, each in its own file, each leaving a note where it acted that the page turns into a plain sentence with a link to its code. With MEND on, Ken's Cinderella comes out byte for byte as without it, at 4 and at 24 frames a second.

Found: several repairs supply what Ken's code names but never wrote. A scene asks characters to wander-around, which was never written (M9). makes-fence is named and timed but never given a way to run (M14), and five of fifteen model-written stories stopped on it. A planner calls explore-method-suggestions, never written (M17). And one stops on a comma left out in 1978: Director asked for ymax unevaluated (M20).

How MEND is checked

52 stress stories, each written to break Ani one way, plus two controls and three fables written the way a model would, are each made five ways (as in 1978, with MEND, with MEND and APPEAR, with the switch's set, and with everything), and each result is compared with what the story is expected to do in that mode, frame counts included.

APPEAR: Ani chooses how the characters look

knowledgestage 2, 10 and 11 October

Size and two elements of shape become more of Ani's choices, made by its own machinery after the 102 (pass 1 keeps CP 29's and adds 30), from suggestions with their sources: Ken's knowledge where he wrote it, the revival's where labeled. Shape experts turn the choices into polygons, stars and blobs. Cinderella becomes a small hexagon (shy, and a film that isn't to be flashy), the stepmother a large triangle (strong, and dominating Cinderella), the fairy godmother an eight-pointed star, the Prince a large circle.

Found: a review relabeled "strong suggests large" as the revival's guess and dropped it under the rule against giving back Ken's looks. Ken decided it is his own knowledge, from page 238 of his thesis, where an improved Ani gives a strong friendly ally a large shape; the rule drops only the revival's guesses, and his own knowledge may agree with his 1978 looks (decision 6).

CHANGE: characters who change

knowledgestage 3, 11 October

A story can now change a character, in the form Ken used in a scene he wrote and left commented out, where the fairy godmother causes (change (physical cinderella shabby) (physical cinderella elegant)). Ani takes a fresh look at her, as if she were brand new, with everyone else's choices held as they were (decision 1), and from the next scene on she moves as she has become.

Found: holding the others by resetting only her choice points moved everyone's values, because Ani makes each choice in the light of the choices made before it. The fresh look instead replays pass 1 in its own order, recording each of the others' choices as it was. And Ken's footnote predicted one result: making Cinderella elegant instead of shabby changes nothing in how she moves.

KNOW: the knowledge Ken could have added

knowledgestage 4, 13 October

More words (gentle and rough, nervous and calm, brave and cowardly, ...), more relationships and ways of showing them (helping, following, avoiding), and more feelings (pride, fear, loneliness, ...), each in the style of the file of Ken's it extends, each with its evidence or the revival's reason.

Found: with KNOW, pass 1 on Cinderella is still 1978's byte for byte, but the Introduction changes. Cinderella follows her stepmother, showing the obedience the thesis says Ani had no way to show, and helps the Prince, which Ani had to cancel in 1978. Six tasks now share the scene's time where five did, so the stepmother pushes Cinderella four quicker times instead of five.

Ken's decisions 9 and 10

Pride first slowed a character, and in Kept Apart the stepmother's pride met her joy's speeding up; Ani's planner rejects conflicting changes outright, so pride only cancelled joy. Ken decided pride makes paths smoother and movements more deliberate and leaves speed alone (9), and which of his relationships get ways of showing (10).

Colors, and looks that change

knowledgestage 5, 14 October

A character's color becomes three more choices (brightness, clarity and a hue on a painter's wheel), with a small "semantic net of colors" of the kind the thesis imagines. Looks can change during a scene: joy brightens a character and sadness dims her; Director grows sizes, steps colors and morphs one shape into another.

Found: the review showed that three of the four hues were decided by nothing but the order of the revival's list of hues. Ken chose his own rule instead (decision 11): a character found to be unique should look different from the others (thesis p. 94), applied to hue. Under it the fairy godmother comes out orange, Ken's own 1978 color for her, reached by the rule and not tuned away.

CHANGE shown: Ken's beautified scene plays

knowledgestage 6, 14 October

Ken named the actions change and causes and never defined them. Now a change is shown: the cause goes to the character and transforms her, or she changes as she wanders, every element changing together over the time the largest needs, gradually at Ken's slowest speed, or in an instant when the cause is magical (the revival's rule, labeled).

Found: Ken's own cinderella-beautified, written in 1978 and left commented out with a note that it might never get done, plays for the first time. The fairy godmother goes to Cinderella and, being magical, transforms her at once: her colors become clear, elegant being shabby's opposite; she wanders so the change is seen. 137 frames, where the scene had been 2.

SLIPS and DETAIL

opt-instage 7, 15 October

SLIPS corrects slips in Ken's files, each correction quoting the line it corrects, with a written account of how it changes Cinderella. DETAIL adds three of the "myriad details" the thesis says a better Ani would attend to: deliberateness shaping a character's path, tendencies feeding the scores of the ways of showing, and a scene's rhythm suggesting changes of speed. Both are off unless ticked.

Found: a run confirmed a suspected inversion between Ani's estimate of how long a gradual change takes and how Director runs it: at high speed every change took 3.95 to 4.04 times the estimate, at low speed 0.21 to 0.25 times. And Director's repeat does one step fewer than it counts, so in 1978 the Introduction's moments of joy changed nothing.

The same film in every browser

found on the way15 October

Made in Chrome, Cinderella with SLIPS had an Introduction of 241 frames, not Node's 230. Chrome's sine, cosine, arctangent, logarithm and exponential differ from Node's in the last bit of about one result in thirty, and the difference grew into a different push.

Fixed: the interpreter now carries its own math library, the standard algorithms written out, bit for bit Node's on 6,000,000 test arguments, and a correctly rounded power. Every film is as it was, and the same in every browser.

SEEN: no standing still

repairs15 October, from Ken's testing

Testing the live page, Ken found the end of the beautified scene standing still for about twelve seconds: a part with only feelings in it, whose characters had nothing left to do while their colors brightened. With SEEN, where a character has only changes in a part, she wanders while they run, "so that the changes are apparent", as the thesis puts it (pp. 125–126). Ken approved it, and the switch turns it on.

Found: Ken's own Cinderella reaches such a stretch too, at the end of the Meeting at 24 frames a second, six seconds still. So SEEN is not one of MEND's repairs, which must leave Cinderella as it was: it is an extension of its own.

Every stage

Reviews: what a second pair of eyes caught

From stage 2 on, each stage was built by one agent for the Lisp and another for the page, then handed to a reviewer who had not built it and was asked to break it, often by writing stories of their own. Sixteen of the 71 agents were reviewers. What they caught:

  • The designs: wherever a review showed one of the four Chapter X designs was wrong, the plan took the corrected version.
  • APPEAR: with MEND and APPEAR both on, pass 2 stopped on any story where pass 1 chose "not high" for a movement; one repair mistook APPEAR's new kind of choice for one of pass 1's. Several labels of whose knowledge was whose were wrong.
  • CHANGE: a change that a character only wants, or prevents, was being made: (wants owl (change ...)) would have changed the owl.
  • KNOW: short walks to a moving target left their walkers at places Ani can't measure from, which stopped later scenes; a story's scene named "fear" clashed with Ani's own feeling and is now renamed.
  • Colors: three of four hues came from the order of a list (above).
  • CHANGE shown: one blocker (a change of looks alone stopped pass 2), five major findings, eleven minor, and fifteen stories of the reviewer's own; among them, the film stopping in the middle of a transformation.
  • SLIPS: a correction still counting a change twice, Kept Apart's feelings barely reaching the walks, and scenes cut off mid-activity, which led to two more corrections, a fix to a third, and a twentieth repair.
Throughout

Ken's part: questions, decisions and testing

Ken wrote 53 prompts in nine days and answered 10 multiple-choice questions; Claude did the rest between them, often for hours. His part was the direction and the judgment.

9 and 10 October

A mini-Ani in the Agent Kit

Alongside the revival, Ani was retold in miniature in Ken's Agent Kit, a construction kit for societies of AI and program agents: a Cast reads a story; Personality, Looks, Relationships and Taste suggest how each character moves and looks; the Choice Points settle their arguments in the open and say why; a Method Chooser plans each scene, and a Director writes it as a Logo film. Its knowledge is mostly transcribed from Ani's, into slots anyone can edit, and its default run explains, for instance, that Cinderella is small and slow because she is shy. The kit gained films for it (1.13.0); the mini-Ani came in 1.14.0 and a version with AI voices in 1.15.0, with a write-up of what the kit can and can't express. It shares no code with the revival. It took 8 of the 71 agents.

Method

How these were counted

  1. The cutoff. Everything is counted up to the prompt that asked for this page, 16 October 2026 at 06:47 London time. The work with Claude after it (this page, the guides, and more work on the film page) is left out. Code is counted at the last commit before it (da3927a, 15 October, 23:19).
  2. Days. From Ken's first prompt about Ani (8 October, 09:20) to the cutoff. Hours at work: the hours in which any of Claude's agents took a step. Agent-hours: for each agent, the time from its first step to its last, added up.
  3. Which transcripts. Claude Code keeps a transcript of each session and of each agent it starts. One session did all of the Ani work; no other session worked on it. That session's transcript, its 34 agents' transcripts and the 37 agents' transcripts of its 4 workflows were counted, each once; the copies of agent transcripts kept as task output were not.
  4. The Agent Kit. The same session also worked on the Agent Kit, all of it for the mini-Ani (item 5 of the Chapter X plan), so it is counted here. Its share: 8 agents (one launched directly, and the 7 of the mini-Ani workflow), 1,232 of the tool calls and 0.3 billion of the tokens; in the main conversation, the steps whose tools named the Kit's folder and those after them until the next that named the revival's.
  5. Prompts. The first, quoted above with Ken's permission, is the only one quoted. Messages Ken typed: the transcript's user messages marked as from a human, and messages he typed while Claude was busy, which arrive as queued commands. Not counted: tool results, notifications from agents and background tasks, summaries made when a long conversation was compacted, and his answers to Claude's 10 multiple-choice questions (asked in 5 rounds).
  6. Tool calls are tool-use blocks, each counted once by its id, in all the transcripts. Steps are Claude's responses, each counted once by its message id (a transcript writes one line per block of a response).
  7. Tokens are the usage each response reports: input, output, cache reads and cache writes, counted once per response. Input and the cache figures are exact. Output is recorded in full for the main conversation, but agents' transcripts keep the final output count for only about one response in nine; for the others the recorded figure is partial. So the estimate counts the final figure where there is one, and otherwise the response's visible text and tool input at four characters a token, leaving out its hidden thinking. It is a lower bound.
  8. Agents. Every agent with a transcript before the cutoff: 34 launched one at a time and 37 inside 4 workflows (6 runs, two of them resumed after a usage limit). Sixteen were reviewers: seven launched to review a stage, and nine inside the workflows.
  9. Lines of code count every line, blank lines and comments too, of the files at da3927a. Ken's files run unchanged: the files of his that the pipeline loads in 1978 mode (as the revival's own record of loaded files lists them), decoded from the tape, leaving out compiled files and the files the runs write; 44 files. Lines added and removed come from git log --numstat, merges and binary files left out; "written by hand" leaves out generated reports and goldens, the OCR text, the built pages and the bundle's data.
  10. Tests. npm test run on an export of da3927a: 268 tests, all passing. The film page's end-to-end checks: the check statements in tools/check-film-app.mjs (184 ran in its last full run, on 15 October). Stress stories: the files in test/stories/stress.
  11. Model trials. The drafts kept in the project's trial reports: 7 sets of 15.
